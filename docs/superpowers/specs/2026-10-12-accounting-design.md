# Voice income and expense ledger

User-approved outcome: a new 💰 Kirim-chiqim section supports voice income/expense
records, balance, monthly salary/income/expense reports, history, and cancelling
incorrect records. Balances carry forward across months. Deliver and run locally.

The section selects accounting mode; voice outside it continues to create reminders.
Plain text is also accepted inside the section. Gemini 3.5 Flash-Lite extracts intent,
positive whole-UZS amount, category, description and reporting month/date. Arithmetic
is performed by SQL/application code, never generated by Gemini. Ambiguous amounts,
non-UZS currency, plans rather than actual transactions, and multi-transaction input
are not stored; the user is asked to resend one complete, clear transaction.

Clear transactions save immediately with a cancellable result. Idempotency uses the
Telegram chat/message identity. Cancelled entries remain in history and are excluded
from aggregates. All reads/writes/cancellations are scoped to the internal user ID.
Amounts use integer so'm, maximum 1,000,000,000,000,000. Negative balances are allowed.

Missing month/date defaults to message date in Asia/Tashkent. A stated month without
year uses the message year, with no invented day: store month precision and a nullable
occurred_on. Real transaction dates/months cannot be future. Monthly reports show
income, expenses, salary income, net, opening and closing balance; current balance
is the sum of all active records. History is paginated and shows cancelled status.

Add finance_entries and an Alembic migration without changing existing saved data.
Keep the main Telegram keyboard visible; inline actions handle reports/history/undo.
Leaving the section changes the voice mode. Old navigation callbacks cannot interrupt
another dialog. Undo requires ownership and can safely be repeated.

Use existing audio limits (120 seconds, 5 MiB). Provider errors never create entries.
Financial audio/transcripts and amounts must not be written to application logs.
No bank connections, money transfers, multi-currency, budgets, or export in v1.

Verification: real application journeys with mock external Gemini/Telegram and real
SQLite repositories; month/category arithmetic, cancellation and duplicate handling;
full test suite, Ruff, mypy; local PostgreSQL migration and real synthetic audio check.
